# OneTrace.pro для Magento 2

Подключает магазин на Magento 2 / Adobe Commerce к [OneTrace.pro](https://onetrace.pro) — платформе данных о клиентах (CDP): заказы, покупатели и согласия на рассылку с сервера, трекер сайта, каталог товаров, виджеты рекомендаций, Web Push и письма магазина через OneTrace. Цепочки брошенной корзины, просмотра без покупки, после покупки и возврата клиентов, рекомендации и прогнозы работают сразу после подключения.

[English version](README.md)

- Magento Open Source и Adobe Commerce 2.4.7–2.4.9, PHP 8.2–8.5
- Заказы и их статусы отправляются с сервера через очередь cron с повторами: оформление заказа никогда не ждёт платформу
- Настройки по представлениям магазина: каждое можно подключить к своему проекту; представления одного проекта на других языках переводят его каталог
- Те же события и свойства, что у всех плагинов OneTrace для магазинов, на основе [onetrace-php](https://github.com/OneTracePro/onetrace-php)

## Что передаётся

| Данные | Когда | Как |
|---|---|---|
| `identify` — email, телефон, имя, город, страна, язык | регистрация, вход, изменение аккаунта и адреса, каждый заказ | сервер, секретный ключ |
| Согласие на рассылку | подписка и отписка в магазине: регистрация, личный кабинет, форма в подвале, админка | сервер, вместе с `identify` |
| `order_completed` | заказ оформлен (любое оформление, REST, GraphQL, админка) | сервер |
| `order_paid`, `order_refunded`, `order_cancelled` | счёт оплачен, кредит-нота возвращена, заказ отменён | сервер, один раз на событие заказа |
| `order_shipped` — служба доставки, трек-номер, отгруженные товары | создана отгрузка (админка, REST, модули доставки) — с её трек-номером или когда к ней добавлен первый трек-номер | сервер, один раз на отгрузку |
| `order_delivered` | заказ перешёл в статус из настройки «Статусы доставленного заказа» | сервер, один раз на заказ |
| `add_to_cart`, `remove_from_cart`, `checkout_started` | изменения корзины и страница оформления — для посетителей с cookie трекера или вошедших | сервер |
| `add_to_wishlist`, `remove_from_wishlist` | избранное Magento: добавление, удаление, перенос в корзину (витрина, GraphQL, админка) | сервер |
| `product_viewed`, просмотры страниц | витрина | трекер в браузере, работает с кэшем страниц и Varnish |
| Каталог товаров с остатками | изменения товаров и остатков (заказы, отмены, возвраты, остатки и источники), раз в сутки и кнопка «Выгрузить весь каталог» | сервер, `products.write` |
| `search` | первая страница результатов поиска магазина при включённом «Поиске по товарам» | сервер |

Заказы гостей без cookie трекера связываются по email; последующие события заказа (счёт, возврат) идут от браузера, в котором его оформили, поэтому всё попадает в один профиль.

## Установка

```bash
composer require onetracepro/onetrace-magento2
bin/magento module:enable OneTrace_Connector
bin/magento setup:upgrade
bin/magento setup:di:compile         # в режиме production
bin/magento setup:static-content:deploy
```

1. В проекте OneTrace откройте **Ключи API** и создайте ключ записи (для витрины) и секретный ключ с правом `products.write` (для сервера; добавьте `messages.send`, чтобы письма магазина уходили через OneTrace).
2. В **Магазины → Конфигурация → OneTrace** укажите адрес платформы (домен, по которому вы открываете OneTrace) и оба ключа, нажмите **Проверить подключение**.
3. Убедитесь, что cron Magento работает: очередь отправляется каждую минуту.

## Отгрузки и доставка

- **Отправлен:** каждая отгрузка заказа — одно событие `order_shipped` (вторая посылка — новое событие): служба доставки (название трек-номера или код перевозчика), трек-номер и товары отгрузки; messageId заканчивается номером отгрузки. Ссылку на отслеживание Magento не хранит, поэтому `tracking_url` не передаётся. Отгрузка, созданная с трек-номером, отправляется сразу; без трек-номера — ждёт первого, добавленного позже (кнопка «Добавить трек-номер», REST API, модуль доставки), а если его нет час, cron (`onetrace_shipments`) отправляет её без номера. Следующие трек-номера и отгрузки, созданные до установки модуля, не передаются.
- **Доставлен:** в Magento нет состояния «доставлен». Выберите статусы, означающие «покупатель получил заказ», в **Что передавать → Статусы доставленного заказа** (по умолчанию пусто — ничего не передаётся), например статус «Доставлен» из **Магазины → Статусы заказов**, который ставит модуль доставки или сотрудник. Заказ, перешедший в один из них, один раз отправляется как `order_delivered`. «Complete» (выполнен) означает «счёт выставлен и отгружен», а не «доставлен».
- ИИ онлайн-чата платформы отвечает на «где мой заказ» по службе доставки и трек-номеру из этих событий.

## Письма магазина

Письма Magento — подтверждения заказов, счета, отгрузки, кредит-ноты, регистрация, сброс пароля — могут уходить через почтовую интеграцию вашего проекта OneTrace вместо почтового сервера магазина, со статусами доставки и историей в профиле покупателя. Включается это в разделе **Письма магазина** платформы (в Magento настраивать ничего не нужно); секретному ключу нужно право `messages.send` («Отправка сообщений вручную»). Состояние для представления магазина видно в **Магазины → Конфигурация → OneTrace → Письма магазина**.

- **Как есть** (включена пересылка писем магазина): готовое письмо — тема, HTML, текст, имя отправителя, адрес для ответа и вложения (PDF, PNG, JPEG, GIF, текст, CSV, календарь; до 5 файлов и 5 МБ) — уходит каждому получателю через OneTrace.
- **По шаблонам OneTrace** (письма о заказе, выбранные в платформе): вместо HTML Magento модуль передаёт заказ — номер, страницу заказа (личный кабинет, для гостей — «Заказы и возвраты»), товары с артикулом, картинкой, ссылкой и опциями, суммы, способы оплаты и доставки, адреса, службу доставки, трек-номер и ссылку на отслеживание отгрузки, сумму возврата кредит-ноты, — а OneTrace собирает письмо на языке представления магазина.
- У `order_delivered` и `order_cancelled` нет письма Magento: при включённом шаблоне модуль отправляет их один раз на заказ, когда заказ переходит в статус из «Статусов доставленного заказа» или отменяется.
- **Запасная отправка:** всё, что OneTrace не принял, — нет почтовой интеграции, исчерпана квота сообщений, слишком много писем получателю, нет ответа за 5 секунд — Magento отправляет сам, тем получателям, которых OneTrace не принял (один запрос на получателя, без повторов). Письма с картинками внутри сообщения (`cid:`) или вложениями других типов отправляет Magento. При «Отключить email-коммуникации» не отправляется ничего; письма администраторам (сброс пароля, двухфакторная аутентификация) всегда отправляет Magento.
- Настройки платформы читаются раз в 5 минут и при сохранении настроек модуля.
- Работает с любым способом отправки (sendmail, SMTP, модули SMTP): модуль — первый плагин почтового транспорта Magento (`Magento\Framework\Mail\TransportInterface::sendMessage`, Laminas Mail в 2.4.7, Symfony Mailer в 2.4.8+), вид письма определяется по его шаблону в `TransportBuilder` (свои шаблоны из **Маркетинг → Шаблоны писем** — по шаблону, из которого они созданы).

| Письмо Magento (шаблон) | Вид | Шаблон OneTrace |
|---|---|---|
| Новый заказ (`sales_email_order_template`, `…_guest_template`) | `order_placed` | да |
| Счёт (`sales_email_invoice_template`, гостевой) | `order_paid` | да |
| Отгрузка (`sales_email_shipment_template`, гостевой) — с трек-номером отгрузки | `order_shipped` | да |
| Кредит-нота (`sales_email_creditmemo_template`, гостевой) | `order_refunded` | да |
| — (заказ перешёл в статус «доставлен») | `order_delivered` | только по шаблону |
| — (заказ отменён) | `order_cancelled` | только по шаблону |
| Комментарии к заказу, счёту, отгрузке и кредит-ноте | `order_note` | нет |
| Готов к выдаче (In-Store Pickup) | `order_ready_for_pickup` | нет |
| Подтверждение отмены заказа гостем (ссылка) | `login_link` | нет |
| Новый аккаунт, аккаунт без пароля, аккаунт подтверждён | `account_new` | нет |
| Подтверждение аккаунта (ссылка) | `email_verification` | нет |
| Забыли пароль, напоминание пароля | `password_reset` | нет |
| Пароль изменён | `password_changed` | нет |
| Данные аккаунта изменены | `account_changed` | нет |
| Подтверждение подписки, подписка, отписка | `newsletter_confirmation`, `newsletter_subscribed`, `newsletter_unsubscribed` | нет |
| Избранное другу, «Отправить другу» | `wishlist_shared`, `product_shared` | нет |
| Уведомления о цене и поступлении | `price_alert`, `stock_alert` | нет |
| Форма обратной связи, ошибка оплаты, ошибки cron и импорта (сотрудникам) | — | всегда Magento |
| Копии сотрудникам («Отправлять копию письма о заказе», Bcc и Cc, любой получатель, кроме покупателя заказа) | — | всегда Magento |
| Письма администраторам (`admin_emails_*`, двухфакторная аутентификация, админка) | — | всегда Magento |
| Другие письма Magento и модулей | `other` (вид письма о заказе, если в шаблоне есть заказ) | нет |

Письма владельцу магазина и сотрудникам никогда не идут через OneTrace, даже при включённой пересылке: там они стали бы профилями покупателей. В письме о заказе с копиями сотрудникам письмо покупателя идёт через OneTrace, а копии Magento отправляет только сотрудникам.

Письма со ссылками доступа (`password_reset`, `account_new`, `email_verification`, `login_link`) отправляются без отслеживания кликов, и после отправки у них остаётся только тема.

## Рекомендации и Web Push

- Виджеты из раздела **Сайт → Виджеты** платформы: укажите их идентификаторы для страницы товара и корзины в настройках или добавьте виджет **Рекомендации OneTrace** в **Контент → Виджеты**. Виджет получает текущий товар, категорию и товары корзины.
- Web Push: включите в настройках — модуль отдаёт `/cdp-sw.js` с корня магазина.

## Остатки и «Сообщить о поступлении»

- **Остатки:** у товаров каталога передаётся `stock`, если магазин ведёт учёт: с Inventory (MSI) — количество для продажи на складе сайта (остаток минус резервы открытых заказов и порог «нет в наличии»), без MSI — количество товарной позиции. У конфигурируемого товара — сумма включённых вариантов. Товары без «Управлять остатками», с предзаказом (в том числе по умолчанию магазина) или с таким вариантом передаются без `stock`: ноль у них не значит «распродано». Заказ, отмена, возврат и сохранение остатка (форма товара, REST API, источники) отправляют товар заново. Платформа учитывает остаток, только если в её настройках каталога включён учёт остатков: тогда ноль снимает товар с продажи и работает триггер «осталось мало».
- **«Сообщить о поступлении»:** на странице товара, который нельзя купить, в колонке с информацией о товаре выводится `<div data-cdp-notify="{id товара}">`; трекер рисует в нём форму вида «Сообщить о поступлении» из раздела **Сайт → Формы** платформы, уведомление отправляет цепочка с триггером «Каталог → снова в наличии». Своя ссылка Magento о поступлении товара на таких страницах скрывается. Выключается настройкой **Что передавать → Показывать форму «Сообщить о поступлении»**.
- **Избранное:** добавление в избранное Magento и удаление из него передаются с настройкой «Корзина» — для цепочек снижения цены и поступления в продажу товаров из избранного.

## Языки каталога

Каталог проекта берётся из его первого представления магазина. Остальные представления, подключённые к тому же проекту (тот же адрес и секретный ключ), с другой локалью (**Магазины → Конфигурация → Общие → Настройки локали**) добавляют переводы: названия товаров, ссылки на них в этом представлении, названия категорий и значения видимых характеристик. Платформа показывает рекомендации, виджеты, результаты поиска и письма на языке посетителя.

## Поиск по товарам

Включите **Поиск по товарам** в настройках (поиск должен входить в тариф проекта):

- Страница результатов поиска сохраняет вашу тему и фильтры, но товары, их порядок и количество берутся из OneTrace: словоформы, опечатки, запрос в неверной раскладке, интересы посетителя. Сортировка по цене и фильтры категории и цены передаются платформе.
- В строке поиска при вводе — подсказки трекера: популярные запросы, категории и товары с картинками и ценами.
- Запрос с правилом переадресации («Сайт → Поиск» платформы, например «доставка» → страница доставки) открывает страницу правила вместо результатов. Кэш страниц не хранит переадресации, но популярный запрос, попавший в кэш до появления правила, показывает сохранённые результаты, пока кэш не обновится.
- Фильтры по другим характеристикам, сортировка по названию и любая ошибка платформы оставляют встроенный поиск Magento. Числа в фильтрах считает поиск Magento.

## Бонусные баллы

Включите **Stores → Configuration → OneTrace → What to send → Bonus points**; сама программа (начисление, уровни, доля заказа, которую можно оплатить баллами) настраивается в разделе **Лояльность** платформы, секретному ключу нужны права `loyalty.read` и `loyalty.write`.

- **Корзина и оформление:** вошедший покупатель видит в итогах корзины и в сводке заказа при оформлении баланс, сколько баллов можно списать и сколько начислится за заказ, вводит баллы и нажимает «Списать баллы». Баллы резервируются на платформе на 30 минут; скидка — итог `onetrace_loyalty` (строка в итогах корзины, заказа, счёта, возврата, на страницах заказа и в письмах). Гостю предлагается войти.
- **Заказ:** прямо перед оформлением изменившаяся корзина или истекающий резерв резервируются заново в пределах допустимой доли; заказ подтверждает баллы своим номером (если платформа недоступна, повторяет cron). Отменённые и возвращённые заказы возвращают баллы на платформе.
- **Мой аккаунт → Бонусные баллы:** баланс, баллы в ожидании срока возврата, уровень, скоро сгорающие баллы и последние операции; «Вступить в программу» — для программ со вступлением по заявке; реферальная ссылка с кнопкой копирования и пришедшие по ней друзья; действующие промокоды покупателя.
- **Приглашения:** включите приглашения в платформе (Лояльность → Приглашения). При регистрации код друга — из ссылки `?ref=` (трекер хранит его в cookie `cdp_ref` 30 дней) или из необязательного поля «Код друга» (**What to send → Friend's code field**) — уходит на платформу из cron, и друг получает подарок; пригласивший — баллы за первый заказ друга.

Покупатель находится на платформе по `user_id` (id покупателя), как в событиях заказов.

## Промокоды

Пулы промокодов настраиваются в разделе **Промокоды** платформы; скидку даёт правило корзины магазина. Создайте правило (**Marketing → Cart Price Rules**) с типом **Specific Coupon** и **Use Auto Generation** и привяжите его к пулу в **Stores → Configuration → OneTrace → Promo codes**, по одному в строке:

```
welcome = 12
```

Каждые 5 минут (cron `onetrace_promo_sync`) новые и изменённые уникальные коды пула становятся купонами правила — на одно использование, со сроком кода. Купоны других правил с тем же кодом не трогаются; пулы с общим кодом не синхронизируются — добавьте такой купон в правило сами. События заказов передают купон, и платформа учитывает использование. Секретному ключу нужно право `promo.read`.

## ИИ-бот чата: MCP магазина

ИИ-бот чата OneTrace отвечает покупателям живыми данными магазина и, если вы разрешите, выполняет действия с заказами. Включите **Подключить к боту чата** в **Stores → Configuration → OneTrace → ИИ-бот чата: MCP магазина** и сохраните: модуль подключит свой MCP-сервер (`POST /onetrace/mcp` представления магазина, контракт MCP магазина v1) к боту проекта. Представления одного проекта и сайта используют одно подключение. Секретному ключу нужно право `chats.manage`.

- **Чтение** (включено по умолчанию): заказы покупателя (аккаунта и гостевые с его email), заказ с товарами, оплатой, доставкой и трек-номером, наличие и цены с вариантами настраиваемых товаров, активные способы доставки для страны (у фиксированной ставки за заказ и бесплатной доставки с порогом — цена), CMS-страница из настройки «Страница с условиями возврата».
- **Действия** (выключены, разрешите их в «Что может бот»): отмена неоплаченного заказа (состояния `new` и `pending_payment`, ничего не оплачено; состояния меняет аргумент `cancellableStates` класса `OneTrace\Connector\Model\StoreMcp\Tools` в `di.xml`), заявка на возврат или смену доставки сотрудникам — комментарий к заказу и письмо по «Шаблону письма с заявкой» на адрес из «Заявки сотрудникам». Бот выполняет действие только после согласия покупателя в чате.
- **Покупатели**: вошедшие на сайт подтверждаются автоматически (подписанный токен в приватной секции `onetrace` передаётся в `cdp.chatCustomer()`); гости и покупатели из мессенджеров получают код из 6 цифр на email («Шаблон письма с кодом»; обработчик события `onetrace_store_mcp_send_code` может отправить код сам, например по SMS, и установить `sent` у `transport`). Заказы других покупателей — «не найдены».

## Конфиденциальность

- При включённом **Режиме ограничения cookie** трекер загружается после разрешения cookie посетителем (отключается в настройках).
- Согласия берутся из штатной подписки магазина на рассылку; «Не активирована» (ждёт подтверждения по email) — ещё не подписка.
- Уже переданные данные остаются в проекте OneTrace; профили удаляются там (GDPR).

## Командная строка

```bash
bin/magento onetrace:test --store=1   # проверка обоих ключей представления магазина
bin/magento onetrace:status           # очередь, последняя ошибка, приостановленные представления
bin/magento onetrace:flush            # отправить ожидающее сейчас
bin/magento onetrace:sync-catalog     # выгрузить весь каталог сейчас
```
